# ADR-0007: Release package layout — loose files alongside the exe

**Status:** Accepted (updated — `data/` directory removed; see history below)

Every master push produces a `skock-windows.zip` via GitHub Actions. The zip is a self-contained Windows build. `skock.exe` is the only entry point at the top level; helper binaries live in `bin/`:

```
skock.exe                        Godot client (entry point)
skock.pck                        Packed game resources (scenes, sprites, etc.)
data_skock_windows_x86_64/       .NET runtime assemblies (generated by Godot export)
bin/
  skock-sim.exe                  Headless sim binary
  skock-dockyard.exe             Dockyard session binary
  skock-admiral.exe              Admiral selection binary
  skock-encounter.exe            Encounter fleet binary (opponent fleets embedded)
```

There is no `data/` directory in the release package. All game data is either embedded in the PCK (scenes, sprites) or compiled into the Rust binaries (`skock-admiral` embeds admiral/faction definitions; `skock-encounter` embeds opponent fleet JSONs via `include_str!()`).

## `bin/` for helper binaries

All Rust helper binaries live in `bin/` rather than at the top level — one entry point (`skock.exe`), everything else tucked away. `RunState` resolves binary paths as `bin/<name>.exe` relative to the Godot executable in exported builds, and as `../target/release/<name>.exe` in the editor.

## `OS.HasFeature("editor")` guard in RunState

Binary path resolution differs between exported builds and the editor:

```csharp
var binDir = OS.HasFeature("editor")
    ? Path.GetFullPath(Path.Combine(ProjectDir, "..", "target", "release"))
    : Path.Combine(Path.GetDirectoryName(OS.GetExecutablePath()) ?? "", "bin");
```

Apply this guard to any future binary path resolution.

## History

**Original layout** included a `data/` directory with loose JSON files:
- `data/opponents/jump_1.json … jump_8.json` — opponent fleet definitions
- `data/admirals.json`, `data/factions.json` — admiral/faction catalog

These were removed as the data migrated into Rust binaries:
- Admiral/faction data → `skock-admiral` (ADR-0017)
- Opponent fleet data → `skock-encounter` (ADR-0019)

The original rationale for loose files was that fleet JSONs were passed as filesystem paths to the sim subprocess. ADR-0019 introduced a temp-file bridge: `BattleRenderer` writes the encounter fleet JSON to a temp file for the sim, then deletes it after the battle. This keeps the sim's file-path interface unchanged while allowing the data to be binary-embedded.
