# Release package layout: loose files alongside the exe

Every master push produces a `skock-windows.zip` via GitHub Actions. The zip is a flat, self-contained Windows build:

```
skock.exe                        Godot client
skock.pck                        Packed game resources (scenes, sprites, etc.)
skock-sim.exe                    Headless sim binary
data_skock_windows_x86_64/       .NET runtime assemblies (generated by Godot export)
data/
  admirals.json
  factions.json
  opponents/
    jump_1.json … jump_8.json
```

## Why loose files for `data/`

The opponent fleet JSONs must be loose files because they are passed as filesystem paths to the sim subprocess (`SimRunner.Run(..., fleetBPath)`). The sim is an external process using standard file I/O — it cannot read from inside the PCK. Since those files are forced onto disk anyway, all `data/` files use the same access pattern (`.NET File.ReadAllText`) for consistency. Adding Godot `FileAccess` for some files while others stay on disk would split the file access pattern for no benefit.

The loose `data/` folder also makes balance tuning easier during active development — JSON files are readable and editable next to the exe without unpacking anything.

## Why not read data/ from the PCK

Considered switching `LocalAdmiralStore` and `LocalRunStore` to use Godot's `FileAccess` API (which reads from `res://` and therefore the PCK). Rejected because:

1. Opponent fleet paths are passed to an external process — they must be real filesystem paths regardless.
2. It would create two different file access patterns for files in the same logical directory.
3. During active development, editable data files are an asset, not a liability.

Revisit when the game ships and tamper-resistance becomes a concern.

## `OS.HasFeature("editor")` guard in RunState

`SimBinaryPath` uses this guard to resolve the sim binary differently in exported builds (next to the exe) versus the editor (`../target/release/skock-sim.exe`). The same guard pattern should be applied to any future path resolution that differs between editor and exported contexts.
