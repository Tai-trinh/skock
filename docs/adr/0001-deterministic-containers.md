# Deterministic containers in the simulation engine

The sim must produce byte-identical output for the same seed across any two runs on any machine — including a local client and a remote server running the same binary. Hash maps and hash sets iterate in non-deterministic order in Rust (and most languages), making them a silent source of desyncs that are extremely difficult to track down after the fact. All sim code must therefore use ordered containers only: `BTreeMap` and `BTreeSet` from the standard library, or plain arrays/vecs indexed by a stable ID. `HashMap` and `HashSet` are permitted in non-sim code (server, tooling, renderer) where determinism is not required.
